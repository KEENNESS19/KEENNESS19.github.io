# ROS 2 体系

**一句话定义：ROS 2 = 一套图模型（节点间怎么连）+ 一个通信底座（DDS，见[[DDS]]）+ 一棵空间树（TF）——它管结构和约定，不管传输本身。**

## 内核：为什么"只管结构"是正确的选择

ROS 1 自研通信的教训（中心化 master、无 QoS、TCP 队头阻塞）证明：**通信的正确性需求复杂到必须交给专业标准**。ROS 2 的内核决策是把传输层整体外包给 DDS（QoS、发现、可靠性全盘继承），自己专注三件 DDS 不理解的事：

1. **图模型**：机器人软件 = 一群互相订阅数据的节点。四件套各管一种数据形态——**话题**（持续数据流，传感器/状态）、**服务**（一问一答，配置查询）、**动作**（长任务 + 进度 + 可中止，导航/抓取）、**参数**（节点配置）。
2. **空间树 TF**：所有坐标系按[[坐标变换与齐次矩阵]]组织成树，任意两系间的变换自动链式求解并带时间戳。
3. **节点生命周期**：受控的 configure → activate → deactivate 状态机，解决"订阅者还没就绪发布者就开跑"的启动竞态。

## 规则与行为

**QoS 规则**：ROS 2 的 QoS 参数直接透传 DDS——传感器流 best-effort + KEEP_LAST(1)，指令流 reliable + KEEP_LAST(1)，参数/地图 transient_local。配错的后果与排查见[[DDS]]第 4.1 节。

**TF 规则**：

1. 树不能有环、每个坐标系唯一父节点——违反即变换无定义；
2. 每条边带时间戳，查询时按时间外推/插值——所以发布 TF **必须带正确采集时刻**（时间戳语义见[[数据回放与时间同步]]）；
3. 静态外参（传感器安装）用 static TF 一次性发布，动态外参（里程计）按频率发布——[[传感器标定]]的产出写入这里。

**回调与执行器规则**：节点的回调默认单线程排队执行——回调里写阻塞代码会冻结整个节点（控制频率掉零）。高频率控制环要么独立线程 + 独立执行器，要么沉到实时层（[[嵌入式与 RTOS]]）走桥接。

**包结构规则**：colcon 包 = 代码 + package.xml（依赖声明）+ CMake。依赖关系即构建顺序——"能编译"不等于"依赖写对了"，运行期的发现失败常源于 package.xml 漏声明。

## 抽象：组件化与部署自由

抽象层是**组件（composable node）**：同一个节点代码，既能编译成独立进程（故障隔离），也能动态加载进容器进程（零拷贝、省开销）——部署形态是运行期决定而非编译期。再往上，launch 系统把"哪些节点、什么参数、什么 QoS、什么 remap"写成可组合的启动描述。至此机器人软件的开发循环完整：**节点写逻辑 → QoS 定契约 → TF 定空间 → launch 定拓扑**——与本站[[软件架构模式]]的分层原则互为表里。
