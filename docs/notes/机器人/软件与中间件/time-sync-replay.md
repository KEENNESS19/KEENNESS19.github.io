# 数据回放与时间同步

**一句话定义：时间同步让多机的"同时"有定义；录包把现场变成可反复重放的数据——两者合起来，调试才能从"守株待兔"变成"案头作业"。**

## 内核：为什么时间戳是一等公民

分布式系统里每台机器有自己的时钟，且**都不可靠**（晶振漂移、NTP 跳变）。而机器人算法时刻依赖两个问题："这两条数据是不是同时刻的？""事件先后顺序是什么？"——没有统一时间语义，因果全部失效。

更深的一层：**时间戳有语义之分**。采集时刻（传感器曝光/采样瞬间）、接收时刻（驱动收到）、处理时刻（算法消费）三者之间隔着队列与传输延迟。**多传感器融合的观测模型隐含"读数对应某时刻的状态"（[[卡尔曼滤波应用]]的时间戳纪律），用接收时刻冒充采集时刻，高速运动下就是厘米级误差。** 规则由此而来：时间戳必须在**离物理事件最近的地方打**（驱动层、硬件触发），之后全链路透传、只读不改。

同步的两条路：**硬件触发/PTP**（同一晶振或 IEEE 1588 协议，亚毫秒级，LiDAR-相机融合的标配）与**软件估计**（记录收发对，估计偏移与漂移，毫秒级，够用但会跳）。

## 规则与行为

**录包规范**（录了将来要能用的包）：

1. **全覆盖 + 带配置**：所有输入话题 + TF + 参数快照 + QoS 快照一起录——少录一个话题，包就只能看不能重放；
2. **录原始层**：录传感器原始数据而非算法结果（结果可重算，原始数据不可再生）；
3. **命名与索引**：日期 + 场景 + 问题一句话；大包建索引；
4. **重放要带时间**：按原速/变速重放保持消息间隔，否则消费端的时间戳逻辑与真实不符。

**回放纪律**：重放时 `use_sim_time` 打开，让节点跟随包内时钟——否则"现在"与"包里"两套时间打架。

## 抽象：调试协议与数据资产

抽象后的工作流是一套协议：**现场异常 → 触发录包（或环形缓冲自动留最近 N 秒）→ 离线重放定位 → 最小化复现用例 → 修复后用同一包回归验证**。环形缓冲（黑匣子）是关键升级：事故之后才想到录，永远来不及；常转的缓冲让"最近 30 秒"天然保存。

这套流程把"复现"从运气变成工程能力——它与[[整机联调流程]]的检查单、[[测试方法论]]的回归测试共享同一批录包资产。**录包是机器人的测试数据集，时间同步是它的可信度签名。**
